* What to review in =scripts/docneural-export.el=

  This is batch Elisp (run via =make export=), not an installed package.
  It reads a doc corpus of Org node files and emits two static artifacts
  the Synapt theme consumes: =graph.json= and one body-only HTML fragment
  per file under =docs/SLUG.html=.

** RESOLVED Link rewriting lives in a parse-tree filter, not a text regex
   :CODE:

   - =docneural--export-body= rewrites resolvable =id:= links to
     =type=file=, =path= =docs/SLUG.html#ANCHOR= inside a
     =:filter-parse-tree=.  Verify this is the shape the theme's
     NotePreview interceptor expects (it is; see ~/synapt).
   - Why not regex the finished HTML?  ox-html turns unresolvable =id:=
     links into ="[BROKEN LINK:...]"= text that has *already dropped the
     description*; you cannot recover it post-export.
   - Review: unresolved =id:= links are collected into FAILED via the
     SAME filter.  Confirm the (list html (nreverse failed)) ordering —
     HTML must be produced *before* reading failed, because the filter
     pushes onto failed during =org-export-as=.

** RESOLVED Anchor integrity: org-html-prefer-user-labels
   :ANCHORS:

   - The =#ANCHOR= half of a rewritten href must match an =id="..."= the
     target fragment actually carries.  Two kinds of anchor exist:
     heading =:CUSTOM_ID: X= (ox emits =id="X=" always) and pandoc-style
     =<<Node>>= targets.
   - GOTCHA (was 47.5% dangling): by default ox renders a =<<Node>>=
     target with a *generated hash* id (=orgd587c72...=) and discards the
     literal name, so every =#NodeName= cross-node link dangled.  Fix:
     bind =org-html-prefer-user-labels=t= in =--export-html= — then
     =org-html--reference= uses the target's literal =:value= as the id.
   - VERIFIED: the =#Slug==slug= self-target class is now 113/113
     resolving, 0 dead (=make linkcheck=).  This is the exporter's real
     responsibility; =check-anchors.py= gates on it.
   - Hexify symmetry: the filter writes =url-hexify-string= on the anchor
     but ox writes the id LITERALLY; that is correct because browsers
     percent-decode a URL fragment before matching an id
     (=#org%20(mode)%29= → id="org (mode)").  For =Site-map= / =_002d=
     names hexify is the identity, so most anchors match byte-for-byte.
   - A prior hack (rewriting =<<targets>>= to raw-html in the filter) is
     GONE — =org-html-prefer-user-labels= is the documented switch; do
     not reintroduce the hack.

   :DECISION:

** REVIEW First the graph change, because it is a product decision

   =store.visible= (=synapt/src/lib/core/store.svelte.ts=, the =get visible=
   near line 213) now narrows the canvas to the two-hop neighbourhood of the
   selected chapter whenever a chapter IS selected. Before this pass the

   - Is ego-by-default right? My argument: 786 nodes answer no question, 32
     answer the one you arrived with. The chip (=.scope= in

** REVIEW =coCitations()= — the new edge type, and what it claims

   =synapt/src/lib/core/graph.ts=, next to =egoGraph=. It answers: which
   chapters are cited /together with/ this one, by how many chapters. The
   corpus never claims a link that is not there, so these edges are synthesized
   in =store.cociteInto()= and carry their evidence as =context=
   ("co-cited: 3 chapters cite both") — the field the rail and note preview
   already print.

   Two judgement calls worth your eye:
   - /one evidence per citer/: a chapter that links the same page twice counts
     once. Otherwise a single verbose chapter out-ranks three independent ones.
   - only edges whose both ends are already in the ego graph are added, so a
     co-citation never drags an unrelated node onto the canvas.

   Tested in =graph.test.ts= (9 new cases: ranking, the dedup rule, the centre
   never returned, the cap, empty for an uncited page).

** REVIEW The hot-path caches — correct, but they are caches

   =store.index()= replaces =data.nodes.find(...)= in =byId=/=bySlug= and
   rebuilds =nodeViews()= only when the graph object identity changes;
   =store.wire()= indexes all 29,017 links both ways, the same way.
   - =bySlug= keeps the FIRST node for a duplicated slug (a comment explains
     why). =Array.find= did exactly this, so behaviour is unchanged — but if
     you ever want "last wins", this is the line.
   - The invalidation is =!== this.data= / =!== this.data.links=. Anything that
     MUTATES =data= in place (a future live-update from an Emacs socket?) would
     serve a stale index. If you get to that, invalidate on a version counter,
     not identity.
   - This exists because =store.views= used to rebuild a 1,559-entry Map on
     /every hover/. Do not "simplify" it back.

** REVIEW =LinkPeek= — the hover card's restraint rules

   =synapt/src/lib/reader/LinkPeek.svelte= + the pointer handlers in
   =DocReader.svelte= (=openPeek=, =onPeekMove=, =onPeekDown=). The rules that
   keep it out of your way, each of which is a decision:
   - 300 ms hover-intent (a card that fires on the way past a paragraph is
     noise), 420 ms long-press on touch, because touch has no hover.
   - =pointer-events: none= — the card is a label, not a menu. You cannot click
     into it, so it can never steal a click or trap a pointer mid-scroll.
   - it closes on scroll and on chapter change; repositioning per frame would
     cost a layout read every scroll event.
   - the body is the citation sentence from =ctx/<id>.json/ — the same lazy
     file the rail fetches, so the card adds zero bytes to the boot. When a
     reference is not a wire (some prose links point at chapters the exporter
     never wired), the card says so plainly rather than showing nothing.
   QUESTION Is a card that you cannot click into too austere? The alternative
            is a 200 ms grace period before it closes (Feishu does this), which
            costs a second timer and the ability to mis-click.
