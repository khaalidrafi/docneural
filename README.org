#+TITLE: docneural — Org manuals as a wired, interactive site
#+DESCRIPTION: Static docs site for Org-mode manuals: a reading view for humans, a citation graph ("synapses") for everyone, and machine-readable artifacts (llms.txt, ctx/, MCP server) for AI agents.

* What this is

  =docneural= turns a directory of Org-mode manuals into ONE static,
  interactive site, built for two readers at once:

  - a *person* lands in prose — reading view, chapter tree, keyboard
    layer, distraction-free mode, link preview cards — and never has to
    think about the graph;
  - an *agent* fetches =graph.json=, =llms.txt=, a node's citation
    context, the per-manual heading index, or drives the bundled MCP
    server — the same structure, no scraping.

  The graph is the brand: every cross-reference between chapters is a
  *synapse*, and every synapse knows the sentence that created it (the
  =why=, not just the fact).

  It is two GitHub repos plus one corpus source:

  | repo                            | role                                              |
  |---------------------------------+---------------------------------------------------|
  | =khaalidrafi/docneural= (here)  | the site: batch-Emacs exporter + transport pass + Vite/Svelte host + verification gates |
  | =khaalidrafi/docneural-ui=      | the theme: reader components, canvas painter, store, styles |
  | =~/org-docs= (Radicle)          | owns the Org corpus and the =id:= link engine (see =HANDOFF.org=) |

* Quickstart (the demo, latest Org, no configuration)

  #+begin_example
  git clone -b ai/cloud https://github.com/khaalidrafi/docneural.git
  git clone -b ai/cloud https://github.com/khaalidrafi/docneural-ui.git docneural-ui
  git clone -b ai/main  https://github.com/khaalidrafi/org-roam-lite-ui.git
  cd docneural
  make install                       # npm install (once)
  (cd ../docneural-ui && npm install)      # the theme, consumed by path alias
  make demo         # fetch latest Org -> export demo corpus -> linkcheck -> build
  make serve        # http://localhost:4173/
  #+end_example

  The site consumes two siblings by path alias (=vite.config.ts=): the
  theme at =../docneural-ui= (=khaalidrafi/docneural-ui=) and the real roam
  graph UI at =../org-roam-lite-ui= (=khaalidrafi/org-roam-lite-ui= —
  no shim needed since it was published; =make orui-shim= still exists
  for offline work).

  =make demo= exports the bundled =demo/= corpus (a small manual about
  docneural itself — nav headers, stubs, wrapped headers, citations)
  with Org 9.8.10, the latest release. It is the one command that must
  always work from a clean checkout.

* Building your own corpus

  The corpus is =CORPUS/<manual>/*.org=; each file carries a =:ID:=
  drawer, chapters carry =:CUSTOM_ID:= headings, and chapters link to
  each other with =[[id:...]]=. The Emacs, Guix and Org manuals are
  produced by the *org-docs* package (=khaalidrafi/org-docs=, branch
  =ai/main=): =M-x org-docs-import-emacs= / =-import-org= /
  =-import-guix= convert the texinfo sources into =org-docs-dir=
  (=~/docs= on the build machine), rewriting every link to a stable
  =id:= link; =org-docs-update.el= checks upstream versions and
  refreshes STAGED (never in place). The exporter only reads the
  corpus — it never fetches. Point the Makefile at it:

  #+begin_example
  make org-latest
  make export CORPUS=~/docs DOC="org emacs guix" ORG_LOAD=build/org-9.8.10
  make linkcheck
  make summarize    # optional one-line tldrs, BYO key, hash-cached
  make build
  make serve        # http://localhost:4173/
  make verify URL=http://127.0.0.1:4173/   # browser gate (needs
                    # playwright-core: npm install in ../org-roam-lite-ui)
  #+end_example

  The exporter needs Org >= 9.7 (load-bearing:
  =org-html-prefer-user-labels=). Either =make org-latest= and pass
  =ORG_LOAD=build/org-9.8.10=, or use the Org your Emacs already
  bundles.

* What the build produces (all under =.export/=, then =dist/=)

  | artifact            | for whom | what it is                                        |
  |--------------------+----------+---------------------------------------------------|
  | =graph.json=        | both     | nodes + wires, degrees, reading order (slim: no prose) |
  | =docs/SLUG.html=    | humans   | one body fragment per chapter, links rewritten     |
  | =ctx/<id>.json=     | both     | the citation sentences around one node (~1 kB, lazy) |
  | =search/<manual>.json= | humans | every heading + anchor, per manual (lazy)         |
  | =llms.txt=          | agents   | one line per chapter — the map of the corpus       |
  | =llms-full.txt=     | agents   | the corpus as one text file                        |

* Reading keys

  =j/k= scroll · =g d/s/h= jump · =[ ]= prev/next chapter · =y= copy
  link to this heading · =b= save this section · =v= distraction-free ·
  =r= read aloud · =p= build a context pack · =/= palette (docs, section
  headings, commands) · =? <question>= ask this corpus · =?= help.

* For agents (AI integrations)

  - =llms.txt= / =llms-full.txt= / =ctx/=: the fetchable surface.
  - MCP server: =node scripts/mcp-server.mjs --out .export= — stdio
    JSON-RPC exposing =search=, =node=, =neighbours=, =citation-path=
    and =stats= over the exported graph, plus =llms.txt= as a resource
    (see =scripts/mcp-server.mjs=; =make verify= runs its 11 protocol
    cases). Config for an assistant:

    #+begin_example
    { "mcpServers": { "docneural": {
        "command": "node",
        "args": ["scripts/mcp-server.mjs", "--out", ".export"] } } }
    #+end_example

  - Export-time summaries (optional, BYO key): =make summarize= adds a
    one-line =tldr= and three takeaways per node, cached by content
    hash — the LLM runs during the build, so the runtime costs nothing.
  - In the browser: =⧉ llm= copies the page as LLM context (40 kB
    budget, truncation marked); =⧉ pack= bundles every chapter you
    ticked into one markdown file with a token estimate BEFORE you copy;
    the palette's =? <question>= sends a grounded prompt (open page +
    corpus index, answers must cite sections) to YOUR OpenAI-compatible
    endpoint — the key stays in your browser and the corpus is never
    sent anywhere by default.

* The Agent API (metered, zero-dep)

  =scripts/mcp-server.mjs= serves ONE assistant over stdio;
  =scripts/agent-api.mjs= serves ANY agent over HTTP — keys, plans,
  quotas, per-second rate limits and an append-only usage log you can
  invoice from. Same answers, same ranking (the weights are copied, so
  the API, the MCP server and the palette cannot disagree), one file,
  zero dependencies: hosting is a small VM plus a reverse proxy.

  #+begin_example
  node scripts/agent-api.mjs --out .export --port 8787 --keys keys.json
  curl -H "Authorization: Bearer dn_live_..." \
       "http://localhost:8787/v1/search?q=agenda+views"
  curl -X POST -H "Authorization: Bearer dn_live_..." \
       -H "Content-Type: application/json" \
       -d '{"question":"how do I capture todos from mail"}' \
       http://localhost:8787/v1/ask
  #+end_example

  - =keys.json=: ~{"dn_live_xxx": {"plan": "build", "tenant": "acme"}}~
    — plans are =hobby= (1k queries/mo, 1 rps), =build= (50k, 10 rps),
    =scale= (500k, 100 rps); every billable call appends to
    =usage-YYYYMM.jsonl=, refusals are 429 with =Retry-After=.
  - Endpoints: =/v1/search=, =/v1/node=, =/v1/neighbours=,
    =/v1/citation-path=, =/v1/stats=, =/v1/llms.txt= (free — it is the
    map that drives the paid calls), and =POST /v1/ask=.
  - =POST /v1/ask= with =TYPESAFE_API_KEY= set adds Jev (TypeSafe's
    System One model): a typed choice ROUTES the question to a manual —
    Jev answers from the options it is given, so it cannot invent a
    manual, and =none= keeps an out-of-corpus question an honest miss —
    then one yes/no probability per candidate filters the BM25 hits.
    ~70 ms per call, ~$0.042/1M input tokens, BYO key. Without a key it
    degrades to pure BM25, and either way every candidate carries its
    citation sentence: the answer arrives with the proof.
  - Client + question packs: =scripts/jev.mjs=, with a CLI:
    =node scripts/jev.mjs --manuals org,emacs "capture todos from mail"=.

* Verification (run before pushing)

  #+begin_example
  make check        # byte-compile the exporter on the target Org
  make linkcheck    # every rewritten link resolves, every anchor exists
  make verify       # ~50 headless-Chromium assertions against a running site
  #+end_example

  Plus =npx vitest run= (both repos) and =npx svelte-check= (both repos).
  The same set runs in GitHub Actions on every push to =ai/*= branches —
  copy =ci/github-actions.yml= to =.github/workflows/ci.yml= to enable it
  (kept out of =.github/= here so the repo can be pushed with a token
  that lacks the =workflow= scope).
