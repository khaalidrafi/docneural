* The two rules every item here is judged by

  1. *Usability first, design second.* A feature that costs 300 ms of
     first paint or 200 kB on the wire loses to one that does not,
     unless the design item is the reason the docs are readable at all.
  2. *Instant means on a phone.* This project's own machine is a 4 GB
     Celeron; a mid-range Android is the real target. Every number below
     was measured here, so treat it as an upper bound on what a visitor
     pays.

* WOW — the features no other docs site ships (researched 2026-10-12)

  Two research passes: one over Chinese consumer-web engineering (where a
  billion phones on bad networks forced "quality per unit of cost" into a
  discipline), one over what makes documentation sites memorable. Judged here
  by =payoff / (lines of code + runtime cost + new dependency)=, because this
  is a static site built and run by one person on a 4 GB Celeron.

  The rule that came out of both: **the wow must come from data we already
  export.** We have 1,559 nodes, 29,017 wires and the citation sentence for
  every wire (=ctx/<id>.json=). Nobody else has that in a docs site, so the
  graph is the show, not a decoration on it.

** NEXT Link peek cards — hover a cross-reference, read its reason (飞书/Lark)
   :WOW:READ:

   - Feishu and Yuque's killer reading feature: hovering a wiki link pops a
     rich card (title, excerpt, backlink count, open / see-in-graph) after
     ~300 ms. Long-press is the phone equivalent.
   - WHY IT IS ALMOST FREE HERE: the excerpt is already in =ctx/<id>.json= —
     the sentence in which the citation was *made*. That is a better preview
     than any summary, and it is the exact mechanism Hebb's-law branding
     already promises: every wire knows why it exists. Backlink count comes
     from =degreesOf= (=core/graph.ts:9=), title from =store.byId=.
   - Cost: one positioned component (~120 lines), zero deps, zero new bytes —
     it fetches the ctx file the rail would have fetched anyway.
   - Skeptic note: must open on delay and never trap the pointer; a card that
     fights a reader scrolling is worse than no card.
   - SHIPPED and browser-verified. =LinkPeek.svelte= + the pointer handlers in
     =DocReader.svelte=: 300 ms hover-intent (no card at 120 ms, card at
     720 ms), 420 ms long-press on touch, =pointer-events: none= so the card
     can never steal a click, closes on scroll and on chapter change. Measured
     on /Agenda Views/: hovering "Exporting" quotes /"By default, the report
     ignores commented (see Comment Lines) and archived (see…"/ with
     =~/org · 1131 synapses · ↵ follow=.
   - One honest limit found by the gate: not every prose reference is a wire.
     =org--Agenda-Views= has 19 in-prose links, 11 of them wired — the rest

** NEXT Ego-graph by default + co-citation edges — kill the hairball
   :WOW:GRAPH:

   - The honest verdict on Obsidian's global graph is that it answers no
     question a reader has ("so fucking useless" — r/ObsidianMD). What works
     in the viz literature (TopicViz, Argo Lite) is an /ego/ graph: the page
     you are reading, 1-2 hops, plus the reason.
   - =neighborIds= (=core/graph.ts:26=) is 1-hop; extend to depth-2 with a
     visited set, and rank neighbours by /co-citation/: two chapters cited
     together by many others are related even when neither links to the
     other. That pass is O(E) over =data.links= in the browser at click time
     — no export change, no new payload, and it is the one edge type nobody
     in documentation exposes.
   - Ship as: opening ⌁ synapses from a chapter shows /that chapter's/
     neighbourhood with a "whole corpus (1559)" escape hatch, so nothing is
     hidden, only ordered.
   - SHIPPED and browser-verified: =store.scope= ('ego' default, 'corpus' on
     the chip), =egoGraph()= and =coCitations()= in =core/graph.ts= (14 new
     unit cases). Measured on /Agenda Views/: the canvas is fed /32/ nodes out
     of 1,559, the chip reads "=⌁ around Agenda Views (The Org Manual) · 32 of
     1559=", and one click takes it to 786 (every non-stub node) and back.
   - Co-citation edges are synthesized, never claimed: each carries its
     evidence as =context= ("co-cited: 3 chapters cite both"), which is the
     field the rail and note preview already print.
   - NEXT, and the reason this item stays open: the dashed-vs-solid difference
     is only in the data today. The canvas needs to /paint/ a co-citation
     differently (orui's =linkColor= accessor is the seam), or the edges are
     honest but invisible as a category.

     browser): a one-line =tldr= and 3 bullet takeaways per page, stored
     in the slim node. That is what makes "copy as context", search
     results, and the rail readable at a glance — and it costs the
     visitor nothing. Needs a key at build time and a cache keyed by
     file hash so unchanged pages are not re-summarised.

** LATER Explain-a-selection popover
   :LLM:

   - Select text -> floating =explain= -> answer from a BYO-key endpoint,
     with the page's raw Org as the only context. Off unless a key is
     configured; never sends the corpus.

** LATER Read aloud (Web Speech API)
   :ACCESS:

   - =R= speaks the current section using the OS voice. Free, offline,
     no assets, and it is an accessibility feature, not a demo.

** LATER Related-now strip
   :SMART:

   - Cosine similarity over tag vectors, computed client-side from the
     slim graph (1,559 x ~10 dims is nothing), for "reads like this".
     Better than the current afferent list for pages with 792 wires.

** LATER Diff-view for two manuals
   :SMART:

   - Org, Emacs and Guix document overlapping concepts. Select two
     chapters, see the shared citations and the divergent ones. Uses the
     graph only, no new data.

** LATER Print/PDF per manual
   :READ:

   - One =@media print= pass that concatenates a manual in reading order
     with page numbers. Cheap, and people still want paper for manuals.

** LATER Agent-facing polish
   :LLM:

   - =llms-full.txt= per corpus (today it is global), a =/?q=deep+link=
     that pre-runs a search so an agent can hand a human a URL, and
     =Link: <...>; rel="canonical"= headers on the raw =.org= responses.
