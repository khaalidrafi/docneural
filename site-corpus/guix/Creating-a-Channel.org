<<Creating-a-Channel-1>>
*** 6.7 Creating a Channel
:PROPERTIES:
:CUSTOM_ID: creating-a-channel
:CLASS: section
:END:
<<index-personal-packages-_0028channels_0029>> <<index-channels_002c-for-personal-packages>>
Let's say you have a bunch of custom package variants or personal packages that you think would make little sense to contribute to the Guix project, but would like to have these packages transparently available to you at the command line. By creating a /channel/, you can use and publish such a package collection. This involves the following steps:

1. A channel lives in a Git repository so the first step, when creating a channel, is to create its repository:

   #+begin_example
   mkdir my-channel
   cd my-channel
   git init
   #+end_example

2. The next step is to create files containing package modules (see [[id:guix--Package-Modules][Package Modules]]), each of which will contain one or more package definitions (see [[id:guix--Defining-Packages][Defining Packages]]). A channel can provide things other than packages, such as build systems or services; we're using packages as it's the most common use case.

   For example, Alice might want to provide a module called =(alice packages greetings)= that will provide her favorite “hello world” implementations. To do that Alice will create a directory corresponding to that module name.

   #+begin_example
   mkdir -p alice/packages
   $EDITOR alice/packages/greetings.scm
   git add alice/packages/greetings.scm
   #+end_example

   You can name your package modules however you like; the main constraint to keep in mind is to avoid name clashes with other package collections, which is why our hypothetical Alice wisely chose the =(alice packages …)= name space.

   Note that you can also place modules in a sub-directory of the repository; see [[id:guix--Package-Modules-in-a-Sub_002ddirectory][Package Modules in a Sub-directory]], for more info on that.

3. With this first module in place, the next step is to test the packages it provides. This can be done with =guix build=, which needs to be told to look for modules in the Git checkout. For example, assuming =(alice packages greetings)= provides a package called =hi-from-alice=, Alice will run this command from the Git checkout:

   #+begin_example
   guix build -L. hi-from-alice
   #+end_example

   ... where =-L.= adds the current directory to Guile's load path (see [[https://www.gnu.org/software/guile/manual/html_node/Load-Paths.html#Load-Paths][Load Paths]] in GNU Guile Reference Manual).

4. It might take Alice a few iterations to obtain satisfying package definitions. Eventually Alice will commit this file:

   #+begin_example
   git commit
   #+end_example

   As a channel author, consider bundling authentication material with your channel so that users can authenticate it. See [[id:guix--Channel-Authentication][Channel Authentication]], and [[id:guix--Specifying-Channel-Authorizations][Specifying Channel Authorizations]], for info on how to do it.

5. To use Alice's channel, anyone can now add it to their channel file (see [[id:guix--Specifying-Additional-Channels][Specifying Additional Channels]]) and run =guix pull= (see [[id:guix--Invoking-guix-pull][Invoking =guix pull=]]):

   #+begin_example
   $EDITOR ~/.config/guix/channels.scm
   guix pull
   #+end_example

   Guix will now behave as if the root directory of that channel's Git repository had been permanently added to the Guile load path. In this example, =(alice packages greetings)= will automatically be found by the =guix= command.

Voilà!

#+begin_quote
*Warning:* Before you publish your channel, we would like to share a few words of caution:

- Before publishing a channel, please consider contributing your package definitions to Guix proper (see [[id:guix--Contributing][Contributing]]). Guix as a project is open to free software of all sorts, and packages in Guix proper are readily available to all Guix users and benefit from the project's quality assurance process.
- Package modules and package definitions are Scheme code that uses various programming interfaces (APIs). Those may occasionally change, in accordance with our deprecation policy (see [[id:guix--Deprecation-Policy][Deprecation Policy]]), and it is your responsibility as a channel author to adjust your code accordingly.
- Corollary: if you're using an external channel and that channel breaks, please /report the issue to the channel authors/, not to the Guix project.

You've been warned! Having said this, we believe external channels are a practical way to exert your freedom to augment Guix' package collection and to share your improvements, which are basic tenets of [[https://www.gnu.org/philosophy/free-sw.html][free software]]. Please email us at [[mailto:guix-devel@gnu.org][guix-devel@gnu.org]] if you'd like to discuss this.

#+end_quote
