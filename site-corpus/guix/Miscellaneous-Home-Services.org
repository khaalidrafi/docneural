**** 13.4.22 Miscellaneous Home Services [[#Miscellaneous-Home-Services-1][¶]]
:PROPERTIES:
:CUSTOM_ID: Miscellaneous-Home-Services-1
:CLASS: subsection
:END:
This section lists Home services that lack a better place.

**** Beets Service [[#Beets-Service][¶]]
:PROPERTIES:
:CUSTOM_ID: Beets-Service
:CLASS: subsubheading
:END:
The =(gnu home services music)= module provides the following service:

- Variable: *home-beets-service-type* [[#index-home_002dbeets_002dservice_002dtype][¶]] :: [[https://beets.io][Beets]] is a music file and metadata manager that can be used via its command-line interface, =beet=. Beets requires a YAML configuration file and this Guix Home service is to create such file.

The service can be used as follows:

#+begin_src lisp
(service home-beets-service-type
         (home-beets-configuration (directory "/home/alice/music")))
#+end_src

Additional options can be specified via the service wild-card field =extra-options=:

#+begin_src lisp
(service home-beets-service-type
         (home-beets-configuration
          (directory "/home/alice/music")
          (extra-options '("
import:
  move: yes"))))
#+end_src

**** Dictionary Service [[#Dictionary-Service-1][¶]]
:PROPERTIES:
:CUSTOM_ID: Dictionary-Service-1
:CLASS: subsubheading
:END:
The =(gnu home services dict)= module provides the following service:

- Variable: *home-dicod-service-type* [[#index-home_002ddicod_002dservice_002dtype][¶]] :: This is the type of the service that runs the =dicod= daemon, an implementation of DICT server (see [[https://puszcza.gnu.org.ua/software/dico/manual/html_node/Dicod.html#Dicod][Dicod]] in GNU Dico Manual).

  You can add =open localhost= to your =~/.dico= file to make =localhost= the default server for =dico= client (see [[https://puszcza.gnu.org.ua/software/dico/manual/html_node/Initialization-File.html#Initialization-File][Initialization File]] in GNU Dico Manual).

This service is a direct mapping of the =dicod-service-type= system service (see [[id:guix--Miscellaneous-Services][Dictionary Service]]). You can use it like this:

#+begin_src lisp
(service home-dicod-service-type)
#+end_src

You may specify a custom configuration by providing a =dicod-configuration= record, exactly like for =dicod-service-type=, but wrapping it in =for-home=:

#+begin_src lisp
(service home-dicod-service-type
         (for-home
          (dicod-configuration ...)))
#+end_src

**** ReadyMedia Service [[#ReadyMedia-Service][¶]]
:PROPERTIES:
:CUSTOM_ID: ReadyMedia-Service
:CLASS: subheading
:END:
The =(gnu home services upnp)= module provides a service to set up the [[https://minidlna.sourceforge.net/][ReadyMedia]] DLNA (Digital Living Network Alliance) UPnP (Universal Plug and Play) media server.

- Variable: *home-readymedia-service-type* [[#index-home_002dreadymedia_002dservice_002dtype][¶]] :: This is the service type for the =minidlnad= daemon; it is the Home counterpart of the =readymedia-service-type= system service (see [[id:guix--Miscellaneous-Services][=readymedia-service-type=]]). The value for this service type is a =readymedia-configuration=.

The service can be used with a =readymedia-configuration= wrapped in =for-home= like this:

#+begin_src lisp
(service home-readymedia-service-type
         (for-home
          (readymedia-configuration
            (media-directories
             (list (readymedia-media-directory
                     (path "/path/to/media/audio")
                     (types '(A)))
                   (readymedia-media-directory
                     (path "/path/to/media/video")
                     (types '(V)))
                   (readymedia-media-directory
                     (path "/path/to/media/misc")))))))
#+end_src

For details about =readymedia-configuration=, check out the documentation of the system service (see [[id:guix--Miscellaneous-Services][=readymedia-service-type=]]).

**** OCI backed services [[#OCI-backed-services-1][¶]]
:PROPERTIES:
:CUSTOM_ID: OCI-backed-services-1
:CLASS: subsubheading
:END:
The =(gnu home services containers)= module provides the following service:

- Variable: *home-oci-service-type* [[#index-home_002doci_002dservice_002dtype][¶]] :: This is the type of the service that allows to manage your OCI containers with the same consistent interface you use for your other Home Shepherd services.

This service is a direct mapping of the =oci-service-type= system service (see [[id:guix--Miscellaneous-Services][OCI backed services]]). You can use it like this:

#+begin_src lisp
(use-modules (gnu services containers)
             (gnu home services containers))

(simple-service 'home-oci-provisioning
                home-oci-service-type
                (oci-extension
                  (volumes
                    (list
                      (oci-volume-configuration (name "prometheus"))
                      (oci-volume-configuration (name "grafana"))))
                  (networks
                    (list
                      (oci-network-configuration (name "monitoring"))))
                  (containers
                   (list
                    (oci-container-configuration
                     (network "monitoring")
                     (image
                      (oci-image
                        (repository "guile")
                        (tag "3")
                        (value (specifications->manifest '("guile")))
                        (pack-options '(#:symlinks (("/bin/guile" -> "bin/guile"))
                                        #:max-layers 2))))
                     (entrypoint "/bin/guile")
                     (command
                      '("-c" "(display \"hello!\n\")")))
                    (oci-container-configuration
                      (image "prom/prometheus")
                      (network "monitoring")
                      (ports
                       '(("9000" . "9000")
                         ("9090" . "9090")))
                      (volumes
                       (list
                        '(("prometheus" . "/var/lib/prometheus")))))
                    (oci-container-configuration
                      (image "grafana/grafana:10.0.1")
                      (network "monitoring")
                      (volumes
                       '(("grafana:/var/lib/grafana"))))))))
#+end_src

You may specify a custom configuration by providing a =oci-configuration= record, exactly like for =oci-service-type=, but wrapping it in =for-home=:

#+begin_src lisp
(use-modules (gnu services)
             (gnu services containers)
             (gnu home services containers))

(service home-oci-service-type
         (for-home
          (oci-configuration
           (runtime 'podman)
           (verbose? #t))))

(simple-service 'home-oci-provisioning
                home-oci-service-type
                (oci-extension
                  (volumes
                    (list
                      (oci-volume-configuration (name "prometheus"))
                      (oci-volume-configuration (name "grafana"))))
                  (networks
                    (list
                      (oci-network-configuration (name "monitoring"))))
                  (containers
                   (list
                    (oci-container-configuration
                     (network "monitoring")
                     (image
                      (oci-image
                        (repository "guile")
                        (tag "3")
                        (value (specifications->manifest '("guile")))
                        (pack-options '(#:symlinks (("/bin/guile" -> "bin/guile"))
                                        #:max-layers 2))))
                     (entrypoint "/bin/guile")
                     (command
                      '("-c" "(display \"hello!\n\")")))
                    (oci-container-configuration
                      (image "prom/prometheus")
                      (network "monitoring")
                      (ports
                       '(("9000" . "9000")
                         ("9090" . "9090")))
                      (volumes
                       (list
                        '(("prometheus" . "/var/lib/prometheus")))))
                    (oci-container-configuration
                      (image "grafana/grafana:10.0.1")
                      (network "monitoring")
                      (volumes
                       '(("grafana:/var/lib/grafana"))))))))
#+end_src

**** git-annex assistant Service [[#git_002dannex-assistant-Service][¶]]
:PROPERTIES:
:CUSTOM_ID: git_002dannex-assistant-Service
:CLASS: subsubheading
:END:
The =(gnu home services git-annex-assistant)= module provides a service to run the [[https://git-annex.branchable.com/assistant/][git-annex assistant]].

- Variable: *home-git-annex-assistant-service-type* [[#index-home_002dgit_002dannex_002dassistant_002dservice_002dtype][¶]] :: This is the type of the service that runs the assistant. You must supply a =<home-git-annex-assistant-configuration>=.

  The service runs one assistant for each directory provided. For example:

  #+begin_src lisp
  (service home-git-annex-assistant-service-type
           (home-git-annex-assistant-configuration
             (directories '("/path/to/foo" "/path/to/bar"))))
  #+end_src

- Data Type: *home-git-annex-assistant-configuration* [[#index-home_002dgit_002dannex_002dassistant_002dconfiguration][¶]] :: Available =home-git-annex-assistant-configuration= fields are:

  - =package= (default: =git-annex=) (type: package) :: Package that provides =git-annex=.

  - =directories= (default: =()=) (type: list-of-strings) :: List of directories.
