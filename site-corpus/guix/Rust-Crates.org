<<Rust-Crates-1>>
**** 22.8.12 Rust Crates
:PROPERTIES:
:CUSTOM_ID: rust-crates
:CLASS: subsection
:END:
<<index-rust>>
Rust applications (binary crates) and libraries (library crates) are packaged separately. We put our main efforts into applications and only package libraries as sources, utilizing automation with a manual focus on unbundling vendored dependencies.

Rust applications are treated like any other package and named using the lowercase upstream name. When using the Cargo build system (see [[id:guix--Build-Systems][=cargo-build-system=]]), Rust applications should have the =#:install-source?= parameter set to =#f=, as this parameter only makes sense for libraries. When the package source is a Cargo workspace, =#:cargo-install-paths= must be set to enable relevant support.

Rust libraries are hidden from the user interface and managed in two modules:

- =(gnu packages rust-crates)= :: Source definitions imported from Rust packages' =Cargo.lock= via the =crate= importer (see [[id:guix--Invoking-guix-import][Invoking =guix import=]]).

  Imported definitions must be checked and have vendored dependencies unbundled before being contributed to Guix.

- =(gnu packages rust-sources)= :: More complex definitions that need to be full packages. This includes Rust libraries requiring external inputs to unbundle and Cargo workspaces.

  These libraries should have the =#:skip-build?= parameter set to =#t=. For Cargo workspaces, =#:cargo-package-crates= must be set.

  Since they are added manually, they follow the usual naming convention for Guix packages (see [[id:guix--Package-Naming][Package Naming]]), with a =rust-= prefix.

  In the Rust community it is common for multiple incompatible versions of a package to be used at any given time, so all libraries should have a versioned suffix. The versioned suffix is the left-most non-zero digit (and any leading zeros, of course). This follows the “caret” version scheme intended by Cargo. Examples =rust-clap-2=, =rust-rand-0.6=.

  In practice we often package development snapshots of Rust libraries and can't simply identify them by version. In this case, the complete version information can be turned into a version string via =git-version=, for example =rust-pipewire-0.8.0.fd3d8f7= and =rust-pubgrub-0.3.0.b70cf70=.

To avoid merge conflicts with changes from multiple branches, these two modules are maintained by the Rust team (see [[id:guix--Teams][Teams]]).

Rust libraries are not referenced directly. =(guix build-sytem cargo)= provides a =cargo-inputs= procedure to lookup input lists generated by the lockfile importer.

<<index-cargo-inputs>> <<index-define_002dcargo_002dinputs>> <<index-lookup_002dcargo_002dinputs>>
- Procedure: cargo-inputs name [#:module '(gnu packages rust-crates)] :: Lookup Cargo inputs for =name= in =module=, return an empty list if unavailable.

  =name= must be consistent with the one used in lockfile importer invocation, usually matching the variable name of the package:

  #+begin_example
  $ guix import -i gnu/packages/rust-crates.scm crate -f /path/to/Cargo.lock name
  #+end_example

  =module= must export a public interface =lookup-cargo-inputs=, a template is available in the =etc/teams/rust= directory of Guix source tree.

See [[https://guix.gnu.org/cookbook/en/html_node/Packaging-Rust-Crates.html#Packaging-Rust-Crates][Packaging Rust Crates]] in GNU Guix Cookbook, for packaging workflow.
