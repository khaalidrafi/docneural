**** 10.2.2 Attachment options [[#Attachment-options-1][¶]]
:PROPERTIES:
:CUSTOM_ID: Attachment-options-1
:CLASS: subsection
:END:
There are a couple of options for attachments that are worth mentioning.

- <<index-org_002dattach_002did_002ddir>>=org-attach-id-dir= [[#index-org_002dattach_002did_002ddir][¶]] :: The directory where attachments are stored when ‘=ID=' is used as method.

- <<index-org_002dattach_002ddir_002drelative>>=org-attach-dir-relative= [[#index-org_002dattach_002ddir_002drelative][¶]] :: When setting the ‘=DIR=' property on a node using C-c C-a s (=org-attach-set-directory=), absolute links are entered by default. This option changes that to relative links.

- <<index-org_002dattach_002duse_002dinheritance>>=org-attach-use-inheritance= [[#index-org_002dattach_002duse_002dinheritance][¶]] :: By default folders attached to a heading are inherited from parents according to =org-use-property-inheritance=. If one instead want to set inheritance specifically for Org attach that can be done using =org-attach-use-inheritance=. Inheriting documents through the node hierarchy makes a lot of sense in most cases. Especially when using attachment links (see [[id:org--Attachment-links][Attachment links]]). The following example shows one use case for attachment inheritance:

  #+begin_example
  * Chapter A ...
    :PROPERTIES:
    :DIR: Chapter A/
    :END:
  ** Introduction
  Some text

  #+NAME: Image 1
  [[attachment:image 1.jpg]]
#+end_example

  Without inheritance one would not be able to resolve the link to ‘=image 1.jpg=', since the link is inside a sub-heading to ‘=Chapter A='.

  Inheritance works the same way for both ‘=ID=' and ‘=DIR=' property. If both properties are defined on the same headline then ‘=DIR=' takes precedence. This is also true if inheritance is enabled. If ‘=DIR=' is inherited from a parent node in the outline, that property still takes precedence over an ‘=ID=' property defined on the node itself.

- <<index-org_002dattach_002dmethod-1>>=org-attach-method= [[#index-org_002dattach_002dmethod-1][¶]] :: When attaching files using the dispatcher C-c C-a it defaults to copying files. The behavior can be changed by customizing =org-attach-method=. Options are Copy, Move/Rename, Hard link or Symbolic link.

- <<index-org_002dattach_002dpreferred_002dnew_002dmethod>>=org-attach-preferred-new-method= [[#index-org_002dattach_002dpreferred_002dnew_002dmethod][¶]] :: This customization lets you choose the default way to attach to nodes without existing ‘=ID=' and ‘=DIR=' property. It defaults to =id= but can also be set to =dir=, =ask= or =nil=.

- <<index-org_002dattach_002darchive_002ddelete>>=org-attach-archive-delete= [[#index-org_002dattach_002darchive_002ddelete][¶]] :: Configure this to determine if attachments should be deleted or not when a subtree that has attachments is archived.

- <<index-org_002dattach_002dauto_002dtag>>=org-attach-auto-tag= [[#index-org_002dattach_002dauto_002dtag][¶]] :: When attaching files to a heading it will be assigned a tag according to what is set here.

- <<index-org_002dattach_002did_002dto_002dpath_002dfunction_002dlist>>=org-attach-id-to-path-function-list= [[#index-org_002dattach_002did_002dto_002dpath_002dfunction_002dlist][¶]] :: When ‘=ID=' is used for attachments, the ID is parsed into a part of a directory-path. See =org-attach-id-uuid-folder-format= for the default function. Define a new one and add it as first element in =org-attach-id-to-path-function-list= if you want the folder structure in any other way. All functions in this list will be tried when resolving existing ID's into paths, to maintain backward compatibility with existing folders in your system.

- <<index-org_002dattach_002dstore_002dlink_002dp>>=org-attach-store-link-p= [[#index-org_002dattach_002dstore_002dlink_002dp][¶]] :: Stores a link to the file that is being attached. The link is stored in =org-stored-links= for later insertion with C-c C-l (see [[id:org--Handling-Links][Handling Links]]). Depending on what option is set in =org-attach-store-link-p=, the link is stored to either the original location as a file link, the attachment location as an attachment link or to the attachment location as a file link.

- <<index-org_002dattach_002dcommands>>=org-attach-commands= [[#index-org_002dattach_002dcommands][¶]] :: List of all commands used in the attach dispatcher.

- <<index-org_002dattach_002dexpert>>=org-attach-expert= [[#index-org_002dattach_002dexpert][¶]] :: Do not show the splash buffer with the attach dispatcher when =org-attach-expert= is set to non-=nil=.

See customization group ‘=Org Attach=' if you want to change the default settings.
